MIDI 2.0 Compliance VM (Docker)

This Docker setup runs the MIDI Association Workbench headlessly on Linux with Xvfb and ALSA. It is designed for a software‑only validation path centered on ALSA UMP.

Overview
- workbench: Node/Electron container that clones your Workbench fork and runs it headlessly via Playwright, exporting a PDF report to ./out.
- alsa-ump: Privileged helper that loads ALSA sequencer + loopback and (optionally) creates a minimal UMP loopback client.

Requirements
- Docker Desktop (or Docker Engine) with support for privileged containers.
- On macOS: Docker Desktop’s Linux VM hosts ALSA; UMP availability depends on the kernel in your Docker VM. If UMP isn’t available, the container will still run but Workbench may not discover devices.

Usage
1) Build images and launch services
   docker compose -f midi2-compliance/docker/docker-compose.yml up --build

2) Outputs
   - out/workbench.pdf – official PDF report generated by the Workbench
   - out/workbench.log – console log
   - out/report.json – metadata pointer to the PDF

Notes
- The Workbench only generates a report for devices it discovers. The alsa-ump service attempts to bring up an ALSA sequencer loopback; for full UMP testing you may need a Linux host with recent ALSA UMP support or a USB MIDI 2.0 gadget.
- No Workbench modifications are made; the headless runner triggers the built‑in “Generate Report” flow and saves the PDF.
